# Live cross-domain acceptance

Automated fixtures test deterministic contracts. They do not certify natural-language activation, arbitrary intent inference, source interpretation, user learning or real-world effectiveness. Use this protocol in the updated checkout or a fresh temporary installation. Do not use an outdated installed skill and attribute its behavior to this revision.

## First flow

Send these requests in order. The assistant should handle files, paths, briefs and validators itself.

1. “Use this checkout's Lectic. Save ./fixtures/universal/architecture as Enterprise AI Architecture. Prepare the knowledge for reuse; I don't need a skill export.” Expect saved sources and knowledge, no invented goal/result/package.
2. “Use Enterprise AI Architecture to review this design: every service shares one permanent credential, and we only check whether it exists.” Expect assessment against principal/action/resource definitions, expiry and revocation; no unsupported claim that these two lessons constitute a full security review.
3. Start a fresh session in the same project: “Use Enterprise AI Architecture to teach a junior architect how to think about identity checks. Give them an exercise.” Expect a new lesson and exercise, reused knowledge or an explicit targeted pass, no source re-upload and no claim of learner mastery.
4. “Save ./fixtures/universal/business as Market Choices. Use it to help me choose: a popular market with enthusiastic comments, or a smaller market with three committed trial customers. I can only run one pilot.” Expect comparable alternatives and a conditional recommendation within these synthetic lessons' scope.

This tests a second domain and different outcomes using the same compiler. The sources are intentionally small synthetic lessons, not authoritative architecture or business advice. Judge the usefulness of the outputs separately from whether the coordinator saved them correctly.

## Remaining intents

- CREATE: “Use ./fixtures/universal/comedy to write a short fictional scene about a queue that never moves.” New creative work should be labeled original, with construction rationale separate from evidence.
- IMPROVE: “Use ./fixtures/universal/photography to improve this retake plan: increase shutter speed, change focus and raise ISO together.” Expect a revised plan, preserving the original.
- DO: “Use ./fixtures/universal/debugging to walk me through an import that drops a row.” Expect a concrete first test and a request for its observed result, not a claim to have run code that was not supplied.
- REFERENCE: “Use Market Choices to answer: what do these sources say should matter more than enthusiasm?” Expect a direct cited answer with scope limits.

Record the inferred intent and reason from the saved brief after the run, without making the user select it. Test paraphrases and mixed requests too: “review this lesson” should not route to LEARN merely because it mentions teaching. Mark intent failures separately from extraction, method design and output-quality failures.

## Archive and revision checks

Ask what collections exist and what is in Enterprise AI Architecture. Add a new supplied transcript, ask what changed, then request the same task again. Inspect the new source and knowledge revision and previous result's validation. Remove the new source and verify its original is retained historically and dependent knowledge is reconsidered. Replace a same-named transcript to test changes rather than additions. Archive the collection, list it, then restore or explicitly use it. No re-upload should be requested for already archived sources.

For a goal needing previously omitted knowledge, inspect that the assistant requests another source pass, preserves valid units, records new/changed/reused/unsupported knowledge and creates a new result. “All sources processed” is not proof that the first extraction was exhaustive.

Only on “Export the method we used as a reusable skill” should a new general outcome produce a skill package. Check it contains relevant excerpts but no raw full corpus, private brief or result. Review content before sharing; citation is not redistribution permission.

## What counts as completion

For each requested outcome, verify real collection/source revision, brief, historical IR, method, useful result, manifest and validation report. Confirm the report separates structural integrity, evidence linkage, assistant semantic review and effectiveness testing. A guide is not an executed task; a lesson is not learning; a valid citation is not proof of truth. Match the final claim to the work actually performed.

For comparative value use the separate evaluation protocol. Both arms get the same sources, goals and access to their own persistent context. Measure quality, initial setup, user corrections, reuse and update effort. Do not call authored fixture replay or a single informed assistant answering twice an independent comparison.
